How I work

Every system I build has a moment where something has to be trusted: an agent's approval, a camera frame, a payment. I design that moment first, and I write down what is still unfinished.

  1. 01

    Verified, not claimed.

    Consent is something a server can check, not a statement an agent makes. Approval goes through the protocol and the agent's own flag is never trusted.

  2. 02

    Unknown is never clean.

    No token, a silent endpoint or an unreadable answer ends in refusal. A gate that opens when it cannot see is not a gate.

  3. 03

    Rules live in code.

    A privacy rule that can be forgotten will be. Asfalya rejects unmasked frames with an exception instead of relying on a checklist.

  4. 04

    Say what is not done.

    Every repository carries a status table with its open items: a recall target missed, a link that is simulation only, a legal permission folder that is still empty.

Asfalya

Road-damage detection from bus-mounted cameras.

In development·Private repository

Details

Phone cameras on municipal buses record the road. Footage is processed overnight on a single GPU: a YOLO model finds potholes, cracks, patches and raised manhole covers, GPS and OSM map-matching pin each one to a street, and sightings across passes collapse into one tracked repair. Results land on a live damage map with weekly PDF reports.

Privacy is enforced in code. Face and plate blurring is a mandatory pipeline step, an unmasked frame is rejected with a PrivacyViolation, and raw video never reaches the server.

Target: Eskişehir pilot, then five buses over twelve weeks. Model v3, mAP50 0.660; multi-pass capture 87.1% against an 85% field target. Phase 5 of 7.

Python · YOLO · Node/Express · PostGIS · MapLibre GL · Docker

Aegis

Source ↗

Network-verified trust for AI agents that spend money.

An MCP server that runs real Google Ads and Meta campaigns behind server-side spending guards. Before a human is ever prompted, it asks the mobile network (GSMA Open Gateway and CAMARA, through Nokia Network-as-Code) whether the approver's line has been taken over.

The agent's own confirm flag is ignored on every path. Approval stops being a story the agent tells and becomes a fact the server can verify.

The trust chain, and where it honestly stands

# Signal Question it answers State
1simSwap.checkWas the approver's line taken over recently?Live
2numberVerificationIs the approval coming from the owner's own device?Simulation only
3deviceStatus.reachabilityCan the line receive data or SMS right now?Live
4deviceStatus.roamingIs the line in the expected country?Live
5deviceSwap.checkWas the line moved to a new device?Live
6callForwardingIs unconditional call forwarding active?Live

Five of six links are verified against live endpoints. The account runs in Nokia's Simulator mode: the wire is proven, the operator integration is not. Number Verification is a device-side OIDC flow that no back end can call.
